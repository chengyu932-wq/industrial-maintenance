# 答辩事实基线

## 系统解决的问题

把分散的设备台账、故障报修、维修执行、备件变化、预防性维护和统计分析连接成可追溯闭环，并以 RBAC 和数据范围隔离五类角色。

## 本人完成的核心工作

1. 39 表数据库和组织、设备、工单、库存、PM、知识、SLA、审计模型。
2. 设备与工单状态机、库存事务、Scheduler 幂等及五角色权限。
3. 规则评分 Top3 派单、TF-IDF/余弦 Top5 推荐和六项真实 KPI。
4. Vue 管理端、ECharts、PDF/Excel、Actuator、备份恢复脚本及自动化验证。

## 可演示主线

管理员确认用户与设备 → 报修人提交故障 → 主管查看 Top3 并派单 → 工程师接单、维修、领用备件、提交验收 → 主管验收 → 设备恢复 → 知识沉淀 → KPI 变化。

## 易被追问的边界

- 智能派单是可解释规则推荐，不替代主管决策。
- 相似推荐是 TF-IDF/余弦，不声称深度学习。
- 一次修复率是首次验收通过率，不声称 7 天同类故障不复发。
- 可用率只统计状态履历覆盖区间，MTBF 只使用人工登记的真实运行小时。
- 附件采用本地目录存储、10 MB 限制和扩展名白名单，已完成设备及工单分类附件的上传、回显和下载；生产化可升级对象存储、内容扫描与生命周期管理。

## 测试结论

全量后端 292/292、真实 MySQL/Redis、生产构建、Chrome 8/8（含五角色登录与附件闭环）、备份恢复和小并发性能均有真实执行证据。系统可用于答辩演示；未在第二台全新主机完成部署，不把本机证据外推为跨机器生产验收。
