# 智能派单算法实验

## 1. 实验目的

验证第9阶段四维加权评分在固定、可复现的数据上，相比“当前在处工单数最低优先”基线的技能、班组、区域匹配表现，并观察其负载均衡代价。本实验不声称该权重为企业最优解。

## 2. 评分公式

实际代码公式为：

`S = 0.40 × S_skill + 0.30 × S_load + 0.20 × S_team + 0.10 × S_area`

- `S_skill = 匹配技能数 / 设备类型所需技能数`；
- `S_load = 1 / (1 + 当前在处工单数)`；
- 同负责班组时 `S_team = 1`，否则为 `0`；
- 同设备所属车间时 `S_area = 1`，否则为 `0`。

无技能要求时技能维度不参与并按剩余权重重新归一化。四项均归一化到 `[0,1]`。

## 3. 数据来源与规模

实验类：`backend/src/test/java/com/cq/maintenance/dispatch/DispatchAlgorithmExperimentTest.java`。

固定数据包括 6 名工程师、3 种设备类型/任务模式和 24 张维修工单。工程师具有固定的初始负载、技能集合、班组和车间；24 张工单按三种任务循环各 8 次。每次分配后立即增加该工程师负载，因此后续工单使用更新后的真实模拟负载。权重使用生产默认值 `40/30/20/10`。

## 4. Baseline

Baseline 每次从全部合法候选中选择当前在处工单数最少者；负载相同按工程师 ID 升序。Baseline 不使用技能、班组或区域信息。

## 5. 评价指标

- 平均技能匹配率：每张工单匹配技能比例的平均值；
- 班组匹配率、区域匹配率；
- 平均综合得分：按生产公式、按候选人在被选择时的负载计算；
- 最终负载变异系数 `CV = 标准差 / 均值`，越低越均衡；
- 最终最大负载与最小负载之差，越低越均衡。

## 6. 运行方式

```powershell
cd D:\BS\industrial-maintenance\backend
.\mvnw.cmd '-Dtest=DispatchAlgorithmExperimentTest' test
```

测试打印 `STAGE9_EXPERIMENT` 结果，并断言加权方案的技能、班组、区域和综合得分均高于 Baseline。输入、Tie Break 与计算过程固定，可重复运行。

## 8. 结果分析

本固定样本中，加权方案优先选择技能、班组和区域更匹配的工程师，因此三项匹配指标和按既定业务权重计算的综合得分均高于 Baseline。最低负载方案的最终负载 CV 和极差明显更低，说明其负载均衡更强；加权方案则出现技能覆盖集中于少数工程师的现象。结果反映的是能力匹配与负载均衡之间的可解释权衡，不代表加权方案在所有数据集上最优。

## 9. 局限性

样本为固定模拟数据，规模仅 24 张工单、6 名工程师，没有排班、工时、技能等级、预计维修时长和真实企业历史。当前负载分 `1/(1+n)` 对高负载人员仍保留正分，且固定权重未经过生产数据标定。后续可在不改变“人工确认”原则的前提下，用脱敏历史工单开展权重敏感性分析。
