# 4 知识沉淀流程

`COMPLETED REPAIR` 工单详情提示沉淀 → 后端校验数据权限、工单类型、终态和维修记录 → 从真实业务表预填草稿 → 创建人/管理者校订 → `DRAFT` 提交为 `PENDING` → 授权主管或管理员审核 → 通过为 `PUBLISHED` 并进入正式知识库，退回为 `REJECTED` 后可修改再提交。创建草稿和审核均不修改库存、工单、SLA 或消息。

# 5 知识状态机

| 当前状态 | 操作 | 目标状态 | 角色 |
|---|---|---|---|
| 无 | 从完成维修工单创建 | `DRAFT` | 工程师、主管、管理员（须有权限和数据范围） |
| `DRAFT` | 编辑 | `DRAFT` | 创建人、范围内主管、管理员 |
| `REJECTED` | 编辑 | `DRAFT` | 创建人、范围内主管、管理员 |
| `DRAFT/REJECTED` | 提交审核 | `PENDING` | 创建人、范围内主管、管理员 |
| `PENDING` | 审核通过 | `PUBLISHED` | 范围内主管、管理员 |
| `PENDING` | 审核退回 | `REJECTED` | 范围内主管、管理员；退回意见必填 |

# 6 知识来源字段

故障现象来自 `mnt_repair_request.fault_description`；根因、维修方法、维修结果分别来自 `mnt_repair_record.root_cause/repair_action/repair_result`；备件来自工单领用量扣除关联退库量后的净使用摘要；设备类型、设备和来源编号由工单关系查询。标题由设备类型与故障现象生成后允许人工修订。

# 7 知识审核

审核人只取当前登录用户，不接受前端 reviewerId。主管审核前调用既有工单数据范围校验；管理员可全局审核。待审核内容锁定，普通工程师不能审核或修改；退回必须填写非空意见，审核人、意见和时间落库。

# 8 TF-IDF数据源

联调时合法历史候选数量：99。工单类型：`REPAIR`；状态：`COMPLETED`；文本字段：仅报修故障描述。过滤 PM、取消/未完成、空描述，并应用当前用户的工单数据范围；按工单推荐时排除工单自身。

# 9 文本预处理

实际采用：无第三方依赖的中文字符 Bigram（字符二元组），不是中文词法分词。先做 NFKC 归一化、英文小写化、去标点/空白，再从资源文件过滤简单停用词；单个汉字保留为单字符特征，英文按单词提取。查询和历史语料共用同一组件。主轴、轴承、伺服、液压、振动、异响等领域词未列为停用词。

# 10 TF公式

`TF(t,d) = count(t,d) / totalTerms(d)`。

# 11 IDF公式

`IDF(t) = ln((N + 1) / (df(t) + 1)) + 1`，其中 N 为合法历史文档数，df 为包含特征 t 的历史文档数。

# 12 余弦相似度

`cos(A,B) = (A·B) / (||A|| × ||B||)`。实现将结果限定在 `[0,1]`，任一向量范数为 0 时返回 0，不产生 NaN 或 Infinity。

# 13 Top5规则

先对全部合法候选建立共同词表和 IDF，再计算查询与候选向量；过滤 `similarity <= 0`，按相似度降序、完成时间降序、工单 ID 升序稳定排序，最多返回 5 条，不足 5 条返回实际数量，不复制结果。

# 14 相似工单返回内容

返回工单 ID/编号、设备 ID/编号/名称、设备类型、故障描述、真实相似度、根因、维修措施、维修结果、完成时间和实际备件摘要，不返回无关人员或隐私字段。

# 15 算法边界处理

空文本由参数校验或空 Token 安全处理；无历史数据返回空列表；查询零向量、无共同特征返回空列表；脏标点和大小写经统一预处理；候选 SQL 排除空描述和非法工单；历史维修扩展字段只用于展示，不参与相似度输入。
