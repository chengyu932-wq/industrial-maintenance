# 论文事实基线

- 技术栈：JDK 17、Spring Boot 3.5.16、Spring Security、MyBatis-Plus 3.5.17、MySQL 8、Redis 8、Vue 3.5.42、Element Plus 2.14.5、ECharts 6.1.0。
- 架构：B/S、前后端分离、单体模块化；不是微服务，不含 IoT 实时采集、消息队列或 AI 诊断。
- 角色：管理员、运维主管、工程师、仓库管理员、报修人。
- 设备状态：RUNNING、FAULT、REPAIRING、STOPPED、SCRAPPED。
- 工单核心状态：PENDING_ASSIGN、PENDING_ACCEPT、IN_PROGRESS、SUSPENDED、PENDING_ACCEPTANCE、COMPLETED、CANCELLED、UNREPAIRABLE。
- 模块：认证/RBAC、组织设备、报修工单、库存、PM、智能派单/SLA、知识/TF-IDF、KPI、消息、审计、系统健康。
- 数据库：39 张业务与支撑表，无 MySQL 物理外键，以索引、唯一约束、CHECK 和 Service 事务维护一致性。
- 智能派单：技能 0.40、负载 0.30、班组 0.20、区域 0.10，归一化后 Top3，主管人工确认。
- 相似推荐：TF-IDF + 余弦相似度，返回 Top5；不是 LIKE，也不是大模型。
- KPI：MTBF=运行小时增量/完成维修数；MTTR=有效维修时长/有效维修数；按时关单率=按时且有 SLA 的完成数/有 SLA 完成数；一次修复率=无验收退回的完成维修数/完成维修数；可用率=RUNNING 时长/有状态履历观测时长；周转率=净消耗/平均库存。
- 时间区间：统计使用左闭右开 `[start, end+1day)`；单次自定义范围不超过一年。
- 附件：设备附件与工单故障/维修/验收附件使用本地目录存储，数据库保存元数据，限制 10 MB 并采用扩展名白名单；已验证上传、列表与下载。
- 最终自动化数字：292/292 通过，失败 0、错误 0、跳过 0；不得沿用早期 277 或 289 项数字。最终 Playwright 为 8/8。
- 当前不足：本机部署为主；运行小时人工登记；算法为规则与传统文本模型；未接工业 IoT；未做第二台主机部署及企业长期高并发验证。
