# 2 KPI口径设计

完整口径、时间边界、权限范围和数据缺口见 [第11阶段 KPI 统计口径设计](第11阶段KPI统计口径设计.md)。

| 指标 | 公式 | 数据来源 | 关键字段 |
|---|---|---|---|
| MTBF | 实际运行小时增量 / 已完成故障维修数 | `eqp_runtime_record`、`mnt_work_order` | `running_hours_increment`、`record_date`、`work_order_type`、`status`、`completed_at` |
| MTTR | 有效 `completed_at - started_at` 总时长 / 有效维修数 | `mnt_work_order` | `started_at`、`completed_at`、`status`、`work_order_type` |
| 工单按时关闭率 | 按 SLA 截止时间前完成数 / 有 SLA 的已完成维修数 | `mnt_work_order` | `completed_at`、`sla_resolve_deadline` |
| 一次修复率 | 目标为 7 天观察窗内未重复故障数 / 可判定首次维修数 | 现有模型不足 | 缺少标准故障分类或重复故障关系，返回 `available=false` |
| 设备综合可用率 | `RUNNING` 履历秒数 / 可观测状态履历秒数 | `eqp_status_log`、`eqp_equipment` | `to_status`、`changed_at`、`equipment_id` |
| 备件周转率 | 净消耗量 / `(期初库存 + 期末库存) / 2` | `inv_transaction`、`inv_stock` | `transaction_type`、`qty_change`、`qty_before`、`qty_after`、`warehouse_id` |

预设范围为近 7/30/90 天和自定义日期，统一由后端解析为左闭右开时间区间。分母为 0 或原始履历不足时返回不可计算状态，不写死 0% 或伪造数据。

# 3 数据模型分析

统计直接复用现有业务事实表：设备与状态履历、运行小时日记录、维修工单与 SLA 截止时间、库存流水与库存余额。未引入统计中间表、数仓、ETL 或缓存。

`sql/23_stage11_statistics.sql` 幂等增加 `eqp_runtime_record(record_date, equipment_id)` 索引；`sql/24_stage11_permissions.sql` 增加统计菜单、`statistics:view` 权限，授予管理员、运维主管、工程师和仓库管理员。一次修复率的不可用是显式数据模型缺口，不将自由文本故障描述冒充标准故障分类。

# 4 后端统计实现

新增独立 `statistics` 模块，按 `StatisticsController -> StatisticsService -> StatisticsMapper -> MySQL` 分层。Service 统一处理时间范围、最长一年的自定义窗口、小数精度、不可用原因和趋势日期补零。Mapper 使用 MySQL `COUNT/SUM/AVG/GROUP BY`、时间区间交集和窗口查询完成批量聚合，没有按设备循环查询。

工单类统计复用 `WorkOrderDataScope`；设备统计依次限制车间、班组或个人范围；库存统计仅查询当前用户授权仓库。Controller 统一要求 `statistics:view`，不接受前端传入的用户或角色代替登录态。

# 5 API

| Method | URL | 权限 | 主要返回 |
|---|---|---|---|
| GET | `/api/statistics/overview` | `statistics:view` | 设备总数、运行/维修设备、期间工单、待处理工单、开放库存预警 |
| GET | `/api/statistics/kpis` | `statistics:view` | 六项 KPI 数值、单位、样本数、公式说明、可用性与缺口原因 |
| GET | `/api/statistics/charts` | `statistics:view` | 六类图表序列与统一统计周期 |

全部接口支持 `range=LAST_7_DAYS|LAST_30_DAYS|LAST_90_DAYS|CUSTOM`；`CUSTOM` 时使用 ISO `yyyy-MM-dd` 的 `startDate` 和 `endDate`。响应继续使用项目统一 `ApiResponse` 外壳。

# 6 前端页面

# 12 问题与风险

严重和较高级别遗留问题：无。

一般风险：一次修复率仍缺少标准故障类别或重复故障关联；`eqp_runtime_record` 尚无完整的业务录入页，没有运行记录时 MTBF 会如实显示数据不足；可用率仅覆盖状态履历实际观测区间。

较低风险：现有主包仍有 Vite 超过 500 kB 的非阻断告警；统计目前适用本科项目数据量，未做百万级数据或延迟性能宣称。
